SeoMedic 왕초보 가이드

컴퓨터·터미널·AI 도구를 처음 다루셔도 괜찮습니다. 아래 순서를 하나씩만 따라오세요.

이 문서와 영문판(GUIDE.en.md)의 내용은 완전히 동일합니다.

0단계. 이 가이드에서 쓰는 용어 (용어집)

용어쉬운 설명
SEO검색엔진 최적화(원문: Search Engine Optimization) — 구글 같은 검색엔진이 내 페이지를 잘 찾도록 만드는 작업
GEO생성형 AI 검색 최적화(원문: Generative Engine Optimization) — ChatGPT·Perplexity 같은 AI 답변에 내 페이지가 인용되도록 만드는 작업
크롤(crawl)프로그램이 웹페이지를 자동으로 방문해 내용을 읽는 것
렌더링(render)브라우저가 코드(HTML/자바스크립트)를 실제 화면 모습으로 그려내는 것
Core Web Vitals(코어 웹 바이탈), LCP구글이 측정하는 "페이지가 얼마나 빠르고 쾌적한지"에 대한 지표 모음. LCP(Largest Contentful Paint)는 그중 하나로 "화면에서 가장 큰 요소가 다 그려지기까지 걸린 시간"을 뜻합니다. 숫자가 작을수록(=빠를수록) 좋습니다
canonical(캐노니컬)"이 페이지의 진짜 대표 주소는 여기입니다"라고 검색엔진에 알려주는 표시
구조화 데이터(JSON-LD)검색엔진이 웹페이지 내용을 더 정확히 이해하도록 돕는 특수한 형태의 숨겨진 정보 표시. 눈에 보이진 않지만 검색결과에 별점·가격·리뷰 같은 추가 정보가 나오게 해주는 원리 중 하나
Open Graph(오픈 그래프)카카오톡·페이스북 같은 곳에 웹페이지 링크를 공유했을 때 나타나는 미리보기(제목·설명·주소)를 결정하는 설정
회귀(regression)예전에 고쳤던 문제가 다시 나빠진 것("원복"과 같은 뜻)
MCPClaude Code가 외부 도구(SeoMedic 엔진 등)와 대화하는 표준 방식
베이스라인(baseline)나중에 비교할 "기준 시점"의 진단 결과 스냅샷
저장소(repository, repo)GitHub에 올라간 프로젝트 코드 전체를 담는 폴더 같은 공간
브랜치(branch)원본을 건드리지 않고 따로 작업할 수 있는 "코드의 가지"(사본 같은 개념)
Pull Request(PR, 풀 리퀘스트)"이렇게 고치는 게 어때요?"라고 저장소 관리자에게 보내는 변경 제안서. 관리자가 검토 후 승인해야만 실제 코드에 반영됨
fork(포크)남의 저장소를 내 계정으로 통째로 복사해오는 것(내 소유가 아닌 저장소를 고치려면 먼저 이렇게 복사해야 함)
Personal Access Token(개인용 접근 토큰)GitHub 비밀번호 대신 특정 프로그램에만 빌려주는 제한된 권한의 열쇠
환경변수(environment variable)프로그램이 컴퓨터에서 읽어가는 설정값 하나(비밀번호처럼 화면에 안 보이게 저장할 때 자주 씀)

1단계. 프로그램 설치 확인 (예상 소요: 5분)

1. Windows는 PowerShell을, Mac은 터미널을 엽니다.

2. 아래를 한 줄씩 입력하고 Enter를 누릅니다.

node -v

성공하면 이렇게 보여요: v22.x.x 같은 버전 번호가 나옵니다. 아무것도 안 나오거나 오류면 README 2단계를 참고해 Node.js를 설치하세요.

3. Claude Code가 실행되는지 확인합니다.

claude --version

성공하면 이렇게 보여요: 버전 번호가 나옵니다. 'claude'은(는) 내부 또는 외부 명령이 아닙니다 같은 오류가 나오면 Claude Code가 아직 설치되지 않은 것입니다 — README 2단계의 링크에서 설치한 뒤 터미널을 새로 열어서 다시 시도하세요.

2단계. SeoMedic 설치 (예상 소요: 3~5분)

1. Claude Code 대화창에 아래를 그대로 입력합니다(이 프로젝트의 실제 저장소 주소·마켓플레이스 이름이라 바꿀 필요 없이 그대로 복사해서 쓰시면 됩니다):

/plugin marketplace add sodam-ai/SoDam-SeoMedic
/plugin install seomedic@sodam-seomedic-marketplace

2. ⭐ 가장 중요한 단계: 설치가 끝나면 Claude Code를 완전히 종료했다가 다시 실행하세요. 창을 닫는 것 정도가 아니라 프로그램 자체를 껐다 켜야 합니다.

3. 다시 켠 뒤 확인:

/plugin list

성공하면 이렇게 보여요: 목록에 seomedic 항목이 "enabled"로 표시됩니다.

3단계. 첫 진단 실행하기 (예상 소요: 1~3분)

1. 대화창에 진단하고 싶은 사이트 주소를 넣어 입력합니다:

/seo-audit https://example.com

2. AI가 "이 사이트가 본인 소유이거나 진단 권한이 있나요?"라고 물어볼 수 있습니다. 맞다면 확인해주세요.

3. 첫 실행이라면 브라우저 엔진 자동 설치로 시간이 조금 더 걸립니다(1~2분).

4. 성공하면 이렇게 보여요:

## SEO 진단 리포트 — https://example.com

**종합 상태: 주의** (참고용 라벨입니다 — 절대 점수가 아닙니다)

- 진단 페이지 수: 1
- 총 위반 건수: 1

## https://example.com/
HTTP 상태: `200`

### Core Web Vitals (lab 측정)
| 지표 | 값 |
|---|---|
| LCP | 784ms |
...

### 위반 사항 (임팩트 순)
| 심각도 | 규칙 ID | 카테고리 | 현재 값 | 권장 조치 |
|---|---|---|---|---|
| 🟠 high | R-CANONICAL-MISSING | canonical | - | self-canonical 추가 권장 |

5. 리포트에 "구조화 데이터가 없습니다" 또는 "Open Graph 제목이 없습니다" 같은 항목이 보일 수 있습니다 — 이건 소셜 공유나 검색결과 표시를 더 풍부하게 만들 수 있는 "기회"이지 심각한 문제는 아닙니다(심각도가 "낮음"으로 표시됩니다).

6. AI 크롤러 정책 항목도 보일 수 있습니다 — 예: "GPTBot이 robots.txt에서 차단되어 있습니다" 같은 안내입니다. ChatGPT·Claude 같은 AI 서비스가 이 사이트를 학습·검색에 활용하도록 허용할지 차단할지는 사이트 운영자가 직접 결정할 문제이며, SeoMedic은 현재 상태만 알려드릴 뿐 "이렇게 바꾸세요"라고 권하지 않습니다.

7. 페이지 제목·제목태그(h1)·이미지 설명(alt) 항목도 보일 수 있습니다 — 예: "title 태그가 없습니다", "h1이 여러 개 발견됐습니다" 같은 안내입니다. 검색엔진이 페이지 내용을 이해하는 데 쓰이는 가장 기본적인 요소들입니다.

8. 상품(Product) 정보 항목도 보일 수 있습니다 — 예: "Product 타입인데 상품명이 누락됐습니다" 같은 안내입니다. 상품 페이지의 구조화 데이터에 Google이 요구하는 필수 정보(상품명, 후기·평점·가격 중 최소 하나)가 빠져 있을 때 나타납니다.

4단계. 나중에 다시 확인하기 (회귀 감지)

1. 진단 결과가 마음에 들면(또는 확인이 끝났으면), 대화창에 이렇게 요청하세요:

이 상태를 베이스라인으로 저장해줘

2. 몇 주/몇 달 뒤, 사이트가 바뀐 후 다시 확인하고 싶다면:

/seo-check https://example.com

3. 성공하면 이렇게 보여요: 문제가 없으면 "베이스라인 대비 원복된 항목이 없습니다", 문제가 생겼으면 어떤 게 다시 나빠졌는지 표로 보여줍니다.

5단계. (선택) 내 Next.js 프로젝트 자동으로 고쳐보기(로컬 폴더)

이 단계는 내 Next.js 프로젝트 소스 코드가 있을 때만 해당됩니다. URL 진단만 쓰신다면 건너뛰어도 됩니다.

1. 대상 프로젝트가 git으로 관리되고 있고, 커밋 안 된 변경사항이 없는지(clean) 먼저 확인하세요.

git status

nothing to commit, working tree clean이 아니면, 먼저 커밋부터 하세요.

2. Claude Code 대화창에 프로젝트 폴더 경로를 넣어 요청합니다:

/seo-fix ./내-nextjs-프로젝트-폴더

3. AI가 계획(무엇을 어떻게 고칠지)을 보여줍니다.

  • "없는 것 추가"는 자동으로 진행됩니다.
  • 검색 결과 표시에 영향을 주는 항목은 변경 내용(diff)을 보여주며 승인 여부를 물어봅니다 — 내용을 확인하고 "승인" 또는 "거부"로 답하세요.

4. 적용이 끝나면 AI가 next build가 통과했는지 알려줍니다. 만약 빌드가 실패하면 자동으로 원래 상태로 되돌아갑니다 — 아무것도 안 하셔도 됩니다.

5. 결과가 마음에 안 들면 "방금 적용한 수정 되돌려줘"라고 요청하세요.

6. 적용된 수정도 실제 파일 변경입니다 — 평소 코드 리뷰하듯 git diff로 한 번 더 확인한 뒤 커밋하세요.

6단계. (선택) GitHub 저장소를 대상으로 자동 수정 제안 받아보기 — ⚠️ 실험적 기능

이 단계는 GitHub에 올려둔 Next.js 프로젝트가 있고, Pull Request(변경 제안)를 받아보고 싶을 때만 해당됩니다. 처음이시라면 먼저 5단계(로컬 폴더)로 익숙해지신 뒤 시도하시길 권합니다. 내 소유 저장소를 대상으로 한 흐름은 실제 GitHub Pull Request 생성까지 전부 검증을 마쳤습니다. 내 소유가 아닌 저장소를 복제(fork)해서 제안하는 흐름은 fork 생성과 복제까지는 실제 GitHub 환경에서 검증했습니다(실제로 fork 저장소가 만들어지는 것까지 확인함). 다만 그 뒤 Pull Request를 실제로 만드는 마지막 단계까지는 아직 확인하지 못했습니다(검증에 사용한 테스트 저장소에 Next.js 프로젝트 파일이 없어 그 앞 단계에서 멈췄습니다). 진행 전 반드시 아래 내용을 확인해주세요.

저작권·라이선스 안내: 이 기능은 GitHub 저장소에 실제로 브랜치·Pull Request를 만듭니다 — 대상 저장소에 대한 권한이 있는지 먼저 확인하시고, SeoMedic 자체의 라이선스·상업적 사용 조건은 README 14번 "법률·저작권·라이선스·상업적 용도"에서 확인해주세요.

1. GitHub 개인용 접근 토큰(Personal Access Token) 만들기

1. 브라우저에서 https://github.com/settings/personal-access-tokens/new 접속 후 로그인

2. Repository access(저장소 접근 범위): "Only select repositories"(특정 저장소만) 선택 → 대상 저장소를 목록에서 선택

3. Repository permissions(저장소 권한): 목록에서 두 가지를 각각 찾아 설정

  • Contents → Read and write
  • Pull requests → Read and write
  • ⚠️ 저장소만 선택하고 이 권한 두 가지를 안 넣으면 나중에 오류가 납니다. 반드시 둘 다 설정하세요.

4. Generate token 버튼 클릭

5. 화면에 초록색 글자로 토큰 값이 딱 한 번 나타납니다. 지금 바로 복사해두세요(창을 닫으면 다시 볼 수 없습니다).

2. ⚠️ 절대로 이 토큰 값을 Claude Code 대화창에 붙여넣지 마세요. 대신 내 컴퓨터에만 등록합니다:

  • Windows: PowerShell을 새로 열고 아래를 입력(따옴표 안을 복사한 토큰으로 교체):
setx SEOMEDIC_GITHUB_TOKEN "여기에_복사한_토큰_붙여넣기"

SUCCESS: Specified value was saved.라는 글자가 나오면 성공입니다.

  • Mac/Linux: 터미널에서:
export SEOMEDIC_GITHUB_TOKEN="여기에_복사한_토큰_붙여넣기"

3. ⭐ 가장 중요한 단계(설치 직후와 같은 이유): Claude Code를 완전히 종료했다가 다시 실행하세요. 이미 켜져 있는 프로그램은 방금 등록한 값을 알지 못합니다.

4. 다시 켠 뒤, Claude Code 대화창에 저장소 주소를 넣어 요청합니다:

/seo-fix https://github.com/소유자이름/저장소이름

5. AI가 진행 전 "이 기능은 아직 실험적입니다"라고 다시 한번 안내합니다. 저장소 주소가 맞는지 확인 후 진행 의사를 밝혀주세요.

6. 로컬 폴더 모드와 다르게, 이번엔 중간에 승인을 묻는 단계 없이 한 번에 끝까지 진행됩니다:

  • "없는 것 추가"에 해당하는 안전한 수정은 자동으로 적용됩니다.
  • 검색 결과 표시에 영향을 주는 항목은 자동 적용되지 않고, "승인이 필요해서 적용하지 않았다"는 목록으로만 알려드립니다.

7. 성공하면 이렇게 보여요: 실제 GitHub Pull Request 링크(https://github.com/.../pull/번호)가 나옵니다. 이 링크를 눌러보면 실제로 어떤 코드가 어떻게 바뀌었는지(diff) 확인할 수 있습니다.

8. 여기서 끝이 아닙니다 — Pull Request는 "제안"일 뿐입니다. 저장소 관리자(본인 또는 팀원)가 GitHub 화면에서 직접 내용을 확인하고 "Merge"(병합) 버튼을 눌러야 실제로 반영됩니다. SeoMedic은 자동으로 병합하지 않습니다.

9. 사용을 마쳤다면, 보안을 위해 만들어둔 토큰을 https://github.com/settings/personal-access-tokens에서 삭제(폐기)하는 것을 권장합니다(특히 짧은 만료기간을 설정하지 않으셨다면).

7단계. 막히면 여기를 보세요

  • 설치·실행 중 문제 → TROUBLESHOOTING.md
  • 궁금한 점 → FAQ.md
  • 전체 기능 설명 → README.md
