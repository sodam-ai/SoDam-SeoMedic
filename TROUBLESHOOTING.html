문제 해결 매트릭스 (TROUBLESHOOTING)

실제로 발생할 수 있는 실패 상황을 상황→증상→해결 순서로 정리했습니다. 여기서 해결이 안 되면 이슈로 알려주세요.

이 문서와 영문판(TROUBLESHOOTING.en.md)의 내용은 완전히 동일합니다.

1. Node.js가 설치되어 있지 않거나 버전이 낮음

  • 증상: 명령 실행 자체가 안 됨, "command not found" 또는 엔진 실행 실패
  • 해결: node -v로 확인(22 이상 필요). 없거나 낮으면 https://nodejs.org 에서 LTS 버전 설치 후 터미널을 다시 열어 재확인.

2. Claude Code 또는 마켓플레이스 설정이 안 됨

  • 증상: /plugin marketplace add 자체가 실패
  • 해결: Claude Code가 최신 버전인지 확인(claude --version), 마켓플레이스 주소(저장소 URL 또는 로컬 경로)가 정확한지 재확인.

3. 설치했는데 완전 재시작을 안 함 (가장 흔한 문제)

  • 증상: /plugin install은 성공했다는데 /seo-audit 명령이 안 뜸
  • 해결: Claude Code 프로그램 자체를 완전히 종료했다가 다시 실행하세요. 새 대화창을 여는 것만으로는 부족합니다(실측 확인된 사실). 재시작 후 /plugin list로 seomedic이 enabled인지 재확인.

4. Playwright 브라우저(Chromium)가 설치 안 됨

  • 증상: 진단 실행 시 브라우저 관련 오류로 실패
  • 해결: 터미널에서 npx playwright install chromium 직접 실행 후 재시도. 사내망/회사 PC라면 다음 항목(방화벽)도 함께 확인.

5. 방화벽·프록시·백신이 다운로드/크롤을 차단

  • 증상: 설치 중 다운로드가 멈추거나, 진단 시 모든 페이지가 실패로 나옴
  • 해결: 회사 네트워크라면 IT 담당자에게 npm 레지스트리(registry.npmjs.org)와 대상 사이트 접근 허용 요청. 개인 PC라면 백신의 "신규 프로그램 차단" 알림을 확인.

6. 인터넷이 느리거나 끊김

  • 증상: 설치·진단이 멈춘 것처럼 오래 걸림
  • 해결: 몇 분 더 기다려보고, 그래도 안 되면 재시도. 최초 설치 시 Chromium(수백MB) 다운로드가 있어 저속 회선에서는 오래 걸릴 수 있습니다.

7. Windows 경로에 한글·공백이 포함됨

  • 증상: 파일 접근 오류, 경로를 못 찾는다는 메시지
  • 해결: 프로젝트 폴더 경로를 영문·숫자 위주로 바꾸거나, 경로 전체를 큰따옴표("...")로 감싸 사용.

8. Windows 권한 문제

  • 증상: .seomedic/ 폴더 생성·파일 쓰기 실패
  • 해결: 관리자 권한이 필요한 폴더(예: C:\Program Files)가 아니라 개인 프로젝트 폴더에서 실행하고 있는지 확인.

9. /seo-fix 실행 시 로컬 서버 기동 실패(포트 충돌 등)

  • 증상: /seo-fix 실행 중 "렌더 브릿지 오류"가 나며 진행이 안 됨
  • 해결: 다른 프로그램이 포트를 과도하게 점유하고 있을 수 있습니다(SeoMedic은 매번 비어있는 포트를 자동으로 찾으므로, 특정 포트를 수동으로 비워줄 필요는 보통 없습니다). 잠시 후 재시도하거나, 대상 프로젝트 폴더에서 직접 npx next build가 정상 동작하는지 먼저 확인해보세요.

10. /seo-fix 대상 프로젝트의 next build 실패

  • 증상: 계획(plan) 단계에서 진단 자체가 안 되거나, 적용(apply) 후 자동으로 되돌려짐(rollback)
  • 해결: 계획 단계 실패라면 대상 프로젝트 폴더에서 직접 npx next build를 실행해 원래부터 빌드가 되는 프로젝트인지 먼저 확인하세요. 적용 후 롤백됐다면 이는 정상 동작입니다(안전장치) — 표시된 build 오류 메시지를 보고 원인을 해결한 뒤 다시 시도하세요.

11. 크롤이 차단됨(robots.txt·403·봇 차단·rate limit)

  • 증상: 진단 결과가 비어있거나 "차단됨" 표시
  • 해결: 본인 소유·권한이 있는 사이트인지 확인. 대상 사이트의 robots.txt가 크롤을 막고 있다면(의도적 보호 조치일 수 있음) 사이트 관리자에게 확인. SeoMedic은 robots.txt를 항상 준수하며 우회하지 않습니다.

12. URL 오타·http 대신 https 필요·의도치 않은 리다이렉트

  • 증상: 진단 실패 또는 예상과 다른 페이지가 진단됨
  • 해결: 주소를 정확히(https:// 포함) 입력했는지 확인. 리다이렉트가 여러 번 발생하면 리포트에 "리다이렉트 체인" 경고가 표시됩니다.

13. 권한 없는 사이트를 진단하려고 함

  • 증상: 진단 실행 전 경고·확인 질문이 뜸
  • 해결: 본인이 소유하거나 진단 권한이 있는 사이트만 대상으로 하세요. 확인 질문에 "예"로 답하기 전에 실제 권한이 있는지 다시 한번 확인하세요.

14. git이 설치 안 됨 또는 작업 폴더가 지저분함(dirty) — /seo-fix 전용

  • 증상: /seo-fix 실행 시 "git 상태가 clean이 아니라 진행할 수 없다"는 메시지와 함께 거부됨
  • 해결: 대상 프로젝트 폴더가 git 저장소인지(git status로 확인), 커밋되지 않은 변경사항이 없는지 확인하세요. 변경사항이 있다면 먼저 커밋하거나 임시로 저장(stash)한 뒤 다시 시도하세요. 이건 의도된 안전장치입니다 — 되돌릴 수 있는 지점이 없으면 자동 수정을 시작하지 않습니다. /seo-audit(진단 전용)은 이 제약과 무관하게 항상 사용할 수 있습니다.

15. 디스크 공간 부족

  • 증상: 설치 실패, Chromium 다운로드 실패
  • 해결: 최소 500MB 이상 여유 공간 확보 후 재시도.

16. OS(Windows/Mac/Linux)에 따라 명령 표기가 다름

  • 증상: 안내 문서의 명령이 내 환경과 다르게 보임
  • 해결: 이 문서의 명령은 OS 공통(Claude Code 대화창 안에서 입력)입니다. 터미널 명령(node -v 등)은 Windows는 PowerShell, Mac/Linux는 터미널 앱에서 동일하게 작동합니다.

17. GitHub 모드 — SEOMEDIC_GITHUB_TOKEN이 설정되지 않았다는 오류

  • 증상: /seo-fix https://github.com/... 실행 시 환경변수가 없다는 메시지와 함께 즉시 거부됨
  • 해결: 토큰을 만들었더라도, 컴퓨터에 등록(setx/export) 후 Claude Code를 완전히 재시작하지 않으면 인식되지 않습니다. 이는 우연한 버그가 아니라 구조적인 이유입니다 — SeoMedic 엔진은 Claude Code가 켜질 때 함께 실행되는 별도 프로그램이라, 이미 켜져 있는 상태에서 새로 등록한 값을 알 방법이 없습니다. GUIDE.md 6단계 3번을 다시 확인하세요.

18. GitHub 모드 — 토큰이 있는데도 "404 Not Found" 오류가 남

  • 증상: 토큰을 등록하고 재시작도 했는데 저장소를 못 찾는다는 오류가 남
  • 해결: 이 오류는 대부분 토큰이 실제로는 그 저장소에 대한 권한을 갖고 있지 않을 때 발생합니다(GitHub은 접근 권한이 없는 저장소를 "권한 없음"이 아니라 "존재하지 않음"으로 답해 보안을 유지합니다). 아래 순서로 확인하세요:

1. https://github.com/settings/personal-access-tokens에서 해당 토큰을 열어 Repository access에 대상 저장소가 실제로 선택되어 있는지 확인

2. Repository permissions에 Contents와 Pull requests가 각각 "Read and write"로 설정되어 있고, 화면 우측 상단 Update 버튼을 눌러 실제로 저장했는지 확인(저장소만 선택하고 권한 저장을 잊는 경우가 흔합니다)

3. 토큰을 만든 GitHub 계정이 그 저장소의 소유자이거나 협업자(collaborator)로 등록되어 있는지 확인

19. GitHub 모드 — Pull Request는 생겼는데 "없는 것 추가" 항목이 하나도 없다고 나옴

  • 증상: 진단은 성공했는데 자동 적용된 수정이 0건이고 Pull Request도 생성되지 않음
  • 해결: 이건 오류가 아니라 정상 동작입니다 — 자동으로 안전하게 고칠 수 있는 문제(예: sitemap에 빠진 페이지)가 실제로 없으면 아무것도 만들지 않습니다. 결과에 나온 "승인이 필요해 적용 안 함" 또는 "제안만 가능" 목록을 확인해, 수동으로 처리할 항목이 있는지 살펴보세요.

20. GitHub 모드 — 실행이 유독 오래 걸림

  • 증상: 로컬 폴더 모드보다 GitHub 모드가 훨씬 오래 걸림
  • 해결: 정상입니다 — GitHub 모드는 저장소를 통째로 내려받고(clone), 의존성을 설치(npm install)하고, 빌드까지 다시 확인하는 과정을 전부 거칩니다. 저장소 크기와 인터넷 속도에 따라 로컬 모드보다 훨씬 오래 걸릴 수 있습니다.

그래도 해결이 안 된다면

증상, 실행한 명령, 화면에 나온 메시지를 그대로 복사해 이슈로 남겨주세요. 스크린샷이 있으면 더 좋습니다. 단, 오류 메시지나 스크린샷에 GitHub 토큰 값이 포함되어 있지 않은지 반드시 먼저 확인한 뒤 공유하세요.
