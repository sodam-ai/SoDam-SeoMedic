자주 묻는 질문 (FAQ)

이 문서와 영문판(FAQ.en.md)의 내용은 완전히 동일합니다.

Q. SeoMedic이 검색 순위를 올려주나요?

아니요. SeoMedic은 진단 도구입니다. 문제를 찾아서 알려줄 뿐, 검색 순위·AI 노출을 보장하지 않습니다. 어떤 도구도 순위를 "보장"할 수는 없습니다.

Q. 내가 만들지 않은 남의 사이트도 진단할 수 있나요?

기술적으로는 가능하지만, 본인 소유이거나 진단 권한이 있는 사이트만 대상으로 해야 합니다. 무단으로 제3자 사이트를 대량 크롤하는 것은 법적 문제가 될 수 있습니다.

Q. 진단하면서 코드를 직접 고쳐주나요?

Next.js 프로젝트라면 가능합니다. 로컬 폴더(/seo-fix ./내-프로젝트-폴더) 또는 GitHub 저장소 주소(/seo-fix https://github.com/소유자/저장소)를 지정할 수 있습니다. "없는 것 추가"는 자동으로, 검색 결과 표시에 영향을 주는 변경은 승인을 받은 뒤에만 실제 파일에 반영합니다. 다른 프레임워크(React, Vue 등)는 아직 지원하지 않습니다.

Q. GitHub 저장소 대상 자동 수정(PR 모드)은 안전한가요?

안전장치는 실제 실행으로 검증됐습니다 — 기본 브랜치 직접 push·강제 push·자동 병합 기능이 코드 구조상 아예 없고, 승인이 필요한 항목은 자동 적용되지 않습니다. 다만 "내가 소유하지 않은 저장소를 fork해서 제안하는 경로"는 아직 실제 GitHub로 검증되지 않은 실험적 상태입니다("내 소유 저장소"에 브랜치+PR을 만드는 경로는 실제로 검증됨). 자세한 내용은 CHECKPOINT_1.5.md를 참고하세요.

Q. GitHub 모드를 쓰려면 왜 토큰이 필요한가요? 비밀번호를 그냥 쓰면 안 되나요?

진짜 GitHub 비밀번호를 쓰면 프로그램이 계정의 모든 것에 접근할 수 있게 됩니다. Personal Access Token은 "이 저장소 하나만, 이런 작업(코드 읽기/쓰기, PR 생성)만" 하도록 범위를 좁힐 수 있는 훨씬 안전한 대체 수단입니다. 자세한 발급 방법은 GUIDE.md 6단계를 참고하세요.

Q. GitHub 토큰을 대화창에 입력해도 되나요?

절대 안 됩니다. 대화 내용은 로그로 남기 때문에, 한 번이라도 입력되는 순간 그 토큰은 노출된 것으로 취급해야 합니다. 반드시 본인 컴퓨터의 환경변수(SEOMEDIC_GITHUB_TOKEN)로만 등록하세요. 실수로 입력했다면 즉시 GitHub에서 해당 토큰을 폐기(삭제)하고 새로 발급하세요.

Q. overall_score 같은 점수가 왜 숫자로 안 나오나요?

의도적인 설계입니다. SEO 점수는 특정 도구의 자체 계산일 뿐 검색엔진의 실제 판단과 다를 수 있어서, "72점" 같은 절대 숫자 대신 "양호/주의/위험" 같은 참고용 라벨로만 보여줍니다.

Q. Core Web Vitals(속도 지표) 수치가 실제 구글 순위 반영 수치와 다른데요?

정상입니다. SeoMedic이 보여주는 수치는 lab 데이터(로컬에서 3회 측정한 값)이고, 구글이 실제 검색 순위에 쓰는 건 field 데이터(CrUX, 실제 방문자들의 데이터)입니다. 이 둘은 원래 다를 수 있습니다.

Q. 내 개인정보나 크롤한 사이트 내용이 어딘가로 전송되나요?

아니요. 텔레메트리(사용 데이터 외부 전송)가 전혀 없습니다. 모든 데이터는 진단을 실행한 내 컴퓨터의 .seomedic/ 폴더(GitHub 모드는 홈 폴더의 .seomedic-github-cache/도 함께) 안에만 저장됩니다.

Q. 크롤한 페이지 내용을 통째로 저장하나요?

아니요. 페이지 원문 전체는 저장하지 않고, 지문(해시)과 500자 이하 짧은 요약만 저장합니다(저작권 보호 목적).

Q. 여러 프로젝트에서 써도 되나요?

네. 한 번 설치하면 어느 프로젝트에서나 사용할 수 있습니다. 다만 진단 결과 데이터베이스는 진단을 실행한 프로젝트 폴더별로 분리되어 저장됩니다.

Q. 무료인가요?

네, SeoMedic 자체는 무료이고 크레딧·과금 없이 로컬에서 실행됩니다. 다만 이 도구를 실행하는 Claude Code 사용료는 별도입니다.

Q. Next.js가 아닌 다른 프레임워크(React, Vue 등)도 진단할 수 있나요?

네, 진단(URL 기반)은 어떤 스택이든 가능합니다. 다만 자동 수정(/seo-fix, 로컬·GitHub 모두)은 현재 Next.js 프로젝트만 지원하고, 그 외 스택은 "이렇게 고치세요" 제안만 나옵니다.

Q. /seo-fix로 수정했는데 마음에 안 들면 되돌릴 수 있나요?

로컬 폴더 모드는 네, 되돌릴 수 있습니다 — "방금 적용한 수정 되돌려줘"라고 요청하면 적용 당시 만들어둔 백업으로 복원합니다. 적용 직후 next build가 실패하면 사람이 요청하지 않아도 자동으로 즉시 원상복구됩니다. GitHub 모드는 결과가 Pull Request(제안)로만 남기 때문에, 마음에 안 들면 그 PR을 그냥 닫으면 됩니다 — 기본 브랜치는 애초에 건드리지 않습니다.

Q. 승인이 필요한(gated) 수정을 승인하지 않으면 어떻게 되나요?

아무 일도 일어나지 않습니다 — 승인하거나 거부하기 전까지 해당 항목은 파일에 반영되지 않은 채로 남아있습니다. GitHub 모드는 대화형 승인 단계가 구조적으로 없어서, 이런 항목은 자동 적용되지 않고 "승인이 필요해 적용 안 함" 목록으로만 보고됩니다.

Q. Pull Request가 생성되면 자동으로 병합(merge)되나요?

아니요, 절대 자동으로 병합되지 않습니다. Pull Request는 어디까지나 "제안"이고, 저장소 관리자가 직접 내용을 검토한 뒤 병합 여부를 결정해야 합니다.

Q. 네이버·빙(Bing)도 지원하나요?

현재는 구글 중심입니다. 네이버·빙 지원은 이후 버전(Phase 3)에서 계획 중입니다.

Q. 회귀 감지는 어떻게 작동하나요?

같은 페이지에서 같은 문제(같은 규칙)를 안정적인 키로 매칭합니다. 베이스라인 저장 시점엔 없던 문제가 이후 진단에서 다시 나타나면 "원복"으로 표시합니다. 의도적으로 만든 변경은 "확인함(acknowledged)"으로 표시해두면 이후 재알림이 없습니다.

Q. 이 도구를 상업적으로 써도 되나요(회사 프로젝트, 고객 납품 등)?

라이선스가 최종 확정(MIT 채택 예정, 저작권자 확정 대기 중)되면 조건 하에 가능할 예정입니다. 현재는 LICENSE 파일이 아직 초안 상태이니, 상업적 배포 전에는 README 14번 항목과 LICENSE 파일을 먼저 확인하시고, 필요하면 법률 전문가의 검토를 받으시길 권장합니다. 이 FAQ는 법률 자문이 아닙니다.
