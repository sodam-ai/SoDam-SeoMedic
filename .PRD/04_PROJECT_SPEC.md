## 배포 형태 = Claude Code 마켓플레이스 플러그인 (확정)

**한 번 설치하면 어느 프로젝트에서나** `/seo-audit`·`/seo-fix`·`/seo-check` 명령으로 사용. 설치:
```text
/plugin marketplace add <user>/seomedic
/plugin install seomedic@<marketplace>
```
> 선례(확인됨): `claude-seo`(AgriciDaniel), `aaron-he-zhu/seo-geo-claude-skills`도 동일하게 마켓 등록·플러그인 설치 방식.

## 아키텍처 — 얇은 플러그인 + MCP 엔진 (확정)

플러그인은 마크다운(명령·스킬)이라 무거운 엔진(Playwright·SQLite)을 직접 못 담음 → **엔진은 npm 배포 MCP 서버로 분리**, 플러그인은 그걸 부르는 얇은 껍데기.

```
seomedic/                         # 마켓플레이스 플러그인 저장소
├── .claude-plugin/
│   └── plugin.json               # name, version(semver), description, license=MIT, repository, keywords
├── commands/                     # /seo-audit.md /seo-fix.md /seo-check.md (슬래시=파일명)
├── skills/
│   └── seomedic/SKILL.md         # 자동 활성 스킬(폴더명=스킬명)
├── .mcp.json                     # 엔진 실행: npx -y @seomedic/mcp  (env로 옵션 전달)
├── SECURITY.md                   # 보안 정책(필수)
├── DISCLAIMER.md                 # 면책·크롤 합법성 고지(필수)
└── README.md                     # 설치·사용법

@seomedic/mcp (npm, 별도 저장소/패키지 = 엔진)
├── crawler/        # 크롤 + Playwright 렌더 + 크롤 안전장치
├── render-bridge/  # (폴더 모드) 로컬 dev/build 서버 기동→URL
├── rules/          # 규칙 모듈(rule_id + rule_version)
├── fixers/         # add_safe / gated + dry-run diff + 멱등 마커 + build 검증
├── github/         # (저장소 모드) 임시 clone→브랜치→PR·fork (git/gh, main 직접 push·force·자동머지 금지)
├── baseline/       # SQLite + finding_key 회귀 비교
└── report/         # Markdown/JSON
```

- **엔진 = MCP 서버**(`npx -y @seomedic/mcp`) → Claude Code가 `audit`/`fix`/`check` 툴로 호출. npm이 의존성·크로스플랫폼 처리.
- **CLI 겸용**(선택): 같은 엔진을 `npx @seomedic/cli`로 CI에서도 사용.
- 플러그인 내부 경로는 **`${CLAUDE_PLUGIN_ROOT}`** 사용(하드코딩 절대 금지 — 설치 위치가 OS·방법마다 다름).

## safe / gated 경계 (확정 — Phase 1.5)

| 변경 유형 | 분류 | 근거 |
|-----------|------|------|
| 빠진 sitemap 항목·신규 OG/Twitter 태그 **추가** | **add_safe**(자동 제안) | "없는 것 추가"는 비파괴적 |
| `title`·`meta` (기존 값 덮어쓰기) | **gated** | CTR/랭킹 신호 |
| `alt` 자동 생성 | **gated/제안만** | 비전 없이 생성 시 이미지 내용 환각 |
| `canonical`·`noindex`·`robots` | **gated** | 색인·표시 직접 통제 |
| `sitemap`(전체)·`JSON-LD` | **gated**(검증 통과 필수) | 잘못된 JSON-LD=리치결과 자격상실+스팸 마크업 수동조치 |

> 원칙: **"색인·표시에 영향을 주는 모든 변경"=gated.** add_safe=순수 추가만(예외 없음).

## 크롤 정책 (범용 배포 = 이게 최우선 안전장치)

- **단일 URL 모드 기본**. 사이트 크롤은 `--site` 명시.
- 사이트모드 기본값: **max-pages 200 · depth 3 · rate-limit 1 req/s** · sitemap 우선.
- **robots.txt 준수** · **식별 가능한 UA** · **audit 대상은 본인 소유·권한 보유 사이트만**(실행 시 경고 배너 + DISCLAIMER 동의).

## 보안·법적 (마켓 배포 필수 — 이전엔 미뤘던 것)

- **텔레메트리·데이터 유출 금지** — 플러그인/엔진은 사용자 동의 없이 외부로 아무것도 전송하지 않음(크롤 대상·사용자 지정 API 제외).
- **시크릿 env-only** — GSC/GA4는 서비스계정 JSON(env 경로), 본인 소유 속성만. 코드 하드코딩·평문 저장 금지.
- **SECURITY.md** — 취약점 보고 경로·범위 명시(선례: claude-seo).
- **DISCLAIMER.md** — "순위/AI 노출 보장 없음", "본인 소유·권한 사이트만", "수정은 승인 후 적용, 무보증", 크롤 합법성은 사용자 책임.
- **권한 최소** — 플러그인이 요구하는 도구 권한(Bash/MCP) 명시.

## 보안 요구사항 (OWASP ASVS · Secure by Design) — 핵심 요구사항(선택 아님)

> 원칙: **Secure by Design** — 보안을 나중에 붙이지 않고 설계에 내장. **모든 외부 입력(URL·URL 파라미터·경로·폼/API 요청값·크롤 응답)은 신뢰하지 않는다.**

**적용 범위 정직 명시**: SeoMedic은 **사용자 계정·웹 서버·결제가 없는 로컬 플러그인/CLI**다. 따라서 웹앱형 항목(로그인, 관리자/일반/비로그인 권한 분리, 앱 세션·쿠키·CORS, nonce·초대·비밀번호 재설정 토큰, 결제)은 **해당 없음(N/A)**이며 이유를 아래 명시한다. 대신 이 도구의 **실제 공격면**(크롤러=SSRF, 렌더 브릿지=명령어 주입, 수정기=경로 조작·소스 주입, 시크릿, 파서, 의존성, 저장)에 집중한다.

## 법률·저작권·라이선스·상업적 이용 요구사항 (핵심 — 선택 아님)

> ⚠️ **법률 자문 아님**: 아래는 PRD 요구사항이지 법적 단정이 아니다. **"법무 검토 필요"** 표시 항목은 실제 공개·배포·납품·상업적 사용 **전에 변호사/전문가 검토**를 받는다. 확인된 사실과 결정 필요를 구분한다.

**적용 배경**: SeoMedic은 **마켓에 공개·배포되고 상업적으로 쓰일 수 있고**, **남의 사이트를 크롤(타인 저작물 접촉)** 하며 **사용자 소스를 수정(파생물 생성)** 한다 → 라이선스·저작권·상표·크롤 콘텐츠 권리가 실질 요구사항.
