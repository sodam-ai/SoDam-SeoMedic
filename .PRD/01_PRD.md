## 1. 제품 개요

### 한 줄 요약
아무 웹/앱 프로젝트든 **URL만 있으면 SEO/GEO 상태를 진단**하고(스택 무관), **Next.js 소스가 있으면 실제 코드를 고쳐주며**(위험 변경은 승인), **나중에 조용히 되돌아간 것까지 잡아주는** — **어느 프로젝트에서나 `/plugin install`로 설치하는 Claude Code 마켓플레이스 플러그인**.

### 해결하는 문제
1. **"분석만 하고 안 고쳐준다"** — 기존 오픈소스/CLI는 리포트만. *(확인됨)*
2. **"자동으로 고쳐주지만 눈속임이다"** — SaaS(OTTO 등)는 JS 런타임 주입 → 구독 끊으면 최적화 소멸, 코드엔 문제 잔존. *(사용자 리뷰 다수 — 일화 근거)*
3. **"남이 만든 사이트는 손댈 수 없다"** — 스택을 모르면 도구가 안 됨.
4. **"조용한 회귀"** — 고친 게 배포되며 소리 없이 원복. *(실무 페인 — 확인됨)*

### 핵심 가치 (차별점)
> 시장은 ①"분석만 오픈소스" vs ②"JS 눈속임 SaaS" 둘로 갈림.
> **빈 공간 = "URL이면 분석, Next.js 소스면 진짜 코드 수정(승인형), 회귀까지 감지."**

- **분석은 스택 무관 / 수정은 Next.js 우선**: 진단은 라이브 URL 렌더 기반이라 어떤 스택이든 가능. **실제 코드 수정은 Phase 1.5에서 Next.js부터**, 다른 스택은 "이렇게 고치세요" 제안만. *(v1.1 정정 — 과약속 제거)*
- **진짜 소스 수정**: JS 주입 아님. `robots.ts`·`sitemap.ts`·`<head>`·JSON-LD를 실제 파일로. Google은 raw HTML canonical을 우선하고 JS 주입 canonical을 불안정 처리. *(확인됨)*
- **승인 게이트 = "색인·표시에 영향을 주는 모든 변경"**: canonical/noindex/robots뿐 아니라 **sitemap·JSON-LD도 검증 통과 + diff 승인** 후에만. *(v1.1 확대 — 잘못된 JSON-LD는 리치결과 자격 상실 + 스팸 마크업 수동조치 위험. Google 공식 확인)*
- **회귀 자동 감지**: 안정 키(페이지URL+규칙ID+규칙버전)로 실행 간 동일 문제를 매칭해 원복 탐지. *(v1.1 — 모델 수정)*
- **크레딧·과금 없음**: 로컬 실행. *(확인됨 — OTTO 최대 불만이 크레딧)*

## 2. 사용자

### 주요 사용자
- **누구**: 여러 웹/앱을 만들거나, 남의 사이트 SEO를 개선해 주는 개발자/바이브코더.
- **상황**: 개발 전(체크리스트) · 중(코딩과 병행) · 후(운영 사이트 진단·개선).
- **목표**: "진단 → (Next.js 소스면) 수정 → 회귀 방지" 반복으로 Google 노출을 실제 개선.

### 사용자 시나리오
**A — 남의 사이트 진단 (분석 전용, 스택 무관)**
1. `/seo-audit https://someone.com`
2. 라이브 URL 크롤·렌더 → 임팩트 순 리포트. 수정은 안 함(소스 없음/권한 없음).

**B — 내 Next.js 진단+수정 (Phase 1.5)**
1. 내 프로젝트에서 `/seo-fix ./my-app --dry-run`
2. 도구가 **로컬 dev/build 서버를 기동해 렌더 진단** → "없는 것 추가"는 자동 제안, 색인영향 변경(canonical/noindex/robots/sitemap/JSON-LD)은 **diff + 승인 대기**
3. `--apply` 승인분만 실제 파일 반영 → **빌드 통과 확인 후** 완료

**C — 회귀 점검**
1. 3개월 뒤 `/seo-check ./my-app`
2. 이전 베이스라인과 안정 키로 비교 → **"고친 7개 중 2개 원복"** 경고. "의도된 변경"은 승인해 베이스라인 갱신.

**D — GitHub 저장소 수정 (PR로 제안)**
1. `/seo-fix github.com/user/repo` (Next.js 저장소)
2. 도구가 **임시 폴더에 clone → 새 브랜치**에 수정(add_safe 자동 / 색인영향은 승인) → **Pull Request(PR) 생성**
3. **내 저장소** = 브랜치+PR / **남의 저장소** = **fork + PR**. **기본 브랜치(main) 직접 push·강제 push·자동 머지 절대 안 함** — 최종 머지는 사람이 검토·결정.

## 4. 사용자 흐름

### 핵심 흐름
```
대상 지정(URL / 폴더 / GitHub 저장소) → 인자 기반 모드 선택
   → [URL] 분석 전용: 크롤·렌더·진단 → 리포트
   → [폴더] 분석+수정(Phase 1.5): 로컬 서버 기동 → 렌더·진단
        → "추가" 자동 제안 + "색인영향" 승인 게이트 → 검증 → 적용 → 빌드확인 → 베이스라인 저장
   → [GitHub 저장소] clone(임시) → 폴더 모드처럼 수정 → 결과를 브랜치+PR로 제출(남의 repo=fork+PR)
   → (재실행) 안정 키 회귀 비교 → 원복/의도 구분 → 경고
```

### 상세 흐름
1. **대상 지정 + 모드 선택**: URL 인자 → 분석 전용. 폴더 인자 + Next.js 감지(package.json+next) → 분석+수정 후보. **GitHub 저장소 인자 → 임시 clone 후 폴더 모드처럼 처리하되 결과는 브랜치+PR로 제출**(내 repo=브랜치+PR, 남의 repo=fork+PR, **main 직접 push·자동 머지 절대 금지**). *("자동 감지"가 아니라 인자 기반 선택 + Next.js 확정 감지. 그 외 스택은 report-only 폴백)*
2. **렌더 브릿지(폴더 모드)**: `next build && next start`(또는 `next dev`) 기동 → 헬스체크 → 로컬 URL 확보 → 그 URL로 크롤·렌더. 포트·타임아웃·기동실패 처리.
3. **진단**: raw vs rendered + CWV + 규칙 검사.
4. **분석 전용 경로**: 리포트만.
5. **수정 경로(P1.5)**: 추가형 제안 자동 / 색인영향 변경은 diff+승인 → 검증(스키마·빌드) → 적용 → 빌드 통과 확인.
6. **베이스라인 저장 / 회귀 점검**: 안정 키로 스냅샷·비교, 원복 vs 의도 구분.

## 5. 성공 기준

### Phase 1 (분석+회귀)
- [ ] **제3자 라이브 URL 1개**를 실제 크롤·렌더해 리포트 생성(목업 아님).
- [ ] **raw HTML vs 렌더드 DOM 차이**를 실제 탐지.
- [ ] **진단 정확도**: known-good/known-bad 픽스처 사이트 세트에서 **핵심 규칙 오탐 0, 재현율 ≥ 90%**(임의 목표, 조정 가능).
- [ ] **CWV 측정 안정성**: Lighthouse **3회 중앙값 + 임계 밴드**로 회귀 오탐 억제. 리포트에 **"lab 값 — Google 랭킹용 field(CrUX)와 다름"** 명시.
- [ ] 같은 프로젝트 두 번 검사 시 **원복 항목 1개 이상** 안정 키로 정확 탐지.

### Phase 1.5 (수정기)
- [ ] Next.js 소스 1개에서 **"추가형"** 수정을 실제 파일로 반영, **적용 후 `build` 통과** 확인.
- [ ] canonical/noindex/robots/sitemap/JSON-LD는 **승인 없이 절대 변경 안 함**(dry-run 기본).
- [ ] fix 2회 실행해도 **중복 삽입 없음(멱등)**, git clean 아니면 **자동 백업/중단**.

### 보안 (핵심 요구사항 — 선택 아님, OWASP ASVS 기준)
- [ ] **SSRF**: 사설/loopback/메타데이터 IP·`file://`·off-host 리다이렉트 크롤 거부.
- [ ] **명령어 주입**: 렌더 브릿지 셸 보간 금지(argv 배열) — 경로에 셸 메타문자 넣어도 미실행.
- [ ] **경로 조작**: 수정은 프로젝트 루트 내 confine, `..` 이탈 거부.
- [ ] **시크릿**: 코드·로그·화면·에러·DB·Git에 키/토큰 0(스캔 통과), env-only.
- [ ] **주입**: SQLite 파라미터화, XML XXE 비활성, 크롤 원격 콘텐츠를 소스에 미주입.
- [ ] **의존성**: `npm audit` 고위험 0(CI 게이트).

## 6. 안 만드는 것 (Out of Scope — Phase 1)

- **JS 런타임 주입 자동수정** — OTTO식 눈속임의 구조적 약점.
- **Next.js 외 스택 자동수정** — Phase 1.5는 Next.js만. 그 외는 제안만.
- **네이버·Bing·Daum·Yandex** — Google 우선. Phase 3.
- **GEO/AEO 본격·AI 노출 보장** — 효과 비결정적. Phase 2에서 입력 위생·프로세스 지표까지만.
- **GSC/GA4/PSI 실데이터·백링크·키워드** — Phase 2+.
- **웹 UI·회원·과금** — 로컬 실행 플러그인(SaaS 아님).
- **프로덕션 직접 수정** — 로컬 소스/스테이징만. *(단, safe 수정도 커밋→배포되면 라이브 도달 = 지연된 프로덕션 영향이므로 재검증 필수)*
